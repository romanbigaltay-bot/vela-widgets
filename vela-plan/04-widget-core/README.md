# P4 — Рантайм виджетов и базовые модули

**Цель этапа:** система, в которую модули вставляются как плагины, и три первых
модуля, доказывающих контракт: часы, заметки, таймер. После этапа добавление
нового модуля — задача на 1–2 дня, а не изменение ядра.

**Оценка:** 8 дней. **Gate:** G4.

| ID | Задача | Приоритет | Дней | Владелец | Зависит от |
|---|---|---|---|---|---|
| T-0401 | Рантайм: реестр, lifecycle, контекст, изоляция | P0 | 2.5 | ui+rust | P3 |
| T-0402 | Хост-карточка, размеры, настройки виджета | P0 | 1.5 | ui | T-0401 |
| T-0403 | Модуль «Часы» | P0 | 1.0 | ui | T-0402 |
| T-0404 | Модуль «Заметки» | P0 | 1.5 | ui+rust | T-0402 |
| T-0405 | Модуль «Таймер / Помодоро» | P0 | 1.5 | ui | T-0402 |

## Порядок

```
T-0401 ──► T-0402 ──┬──► T-0403 ──┐
                    ├──► T-0404 ──┼──► G4
                    └──► T-0405 ──┘
```
Три модуля можно делать параллельно — это и есть проверка контракта: если
модуль требует правки ядра, контракт признан неудачным (см. ниже).

## Критерии выхода (G4)

- [ ] Часы, заметки, таймер добавляются из палитры и живут на холсте.
- [ ] Настройки виджета рендерятся из `settingsSchema` без кода под конкретный модуль.
- [ ] Падение виджета (искусственное исключение) не роняет холст.
- [ ] Три модуля не потребовали изменений в `T-0401` после первого дня работы.
- [ ] Утечек нет: 50 циклов монтирования/размонтирования — память стабильна.
- [ ] Таймеры останавливаются, когда виджет вне вьюпорта или система в suspend.

## Проверка качества контракта

Признак плохого контракта: модулю нужен доступ к DOM холста, к камере или
к другому модулю напрямую. Если такое случилось — не «разрешить исключение»,
а переписать контракт (это дороже сейчас, но дешевле на 5 модулях P7).
