# T-0402 — Хост-карточка

## 1. Цель

Общая рамка для любого виджета: стекло, заголовок, перетаскивание, изменение
размера, настройки. Модуль рисует только внутренности.

## 2. Анатомия

```
┌───────────────────────────────┐
│ название            ⠿   ⋯    │  заголовок (drag handle + меню)
├───────────────────────────────┤
│                               │
│        содержимое модуля      │
│                               │
└───────────────────────────────┘
```

- Заголовок опционален (`manifest.header: false` для декоративных модулей).
- `⋯` — меню: «Настройки», «Дублировать», «Скрыть в профиле», «Удалить».
- Изменение размера: ручка в правом нижнем углу, шаг 8 px, ограничения из
  манифеста (`minSize`, `resizable`).
- Двойной клик по заголовку — «компактный/обычный» (если модуль объявил два размера).

## 3. Настройки из схемы

`settingsSchema` (JSON Schema, упрощённая: `string`, `number`, `boolean`,
`enum`, `color`) → автоматическая форма в поповере. Никакого кода под конкретный
модуль. Изменение — `widget.settings_update` → валидация в Rust → событие
`onSettingsChange`.

## 5. Критерии приёмки

- **AC-1** Ресайз соблюдает `minSize` и шаг 8, сохраняется в БД.
- **AC-2** Форма настроек генерируется для 5 типов полей без кода под модуль.
- **AC-3** Новый виджет появляется в свободном месте вблизи центра вьюпорта,
  без наложения на другие (поиск свободного слота).
- **AC-4** Меню закрывается по `Escape` и по клику вне, фокус возвращается.
- **AC-5** Карточка не «прыгает» при ошибке модуля (плашка того же размера).

## 7. Риски

Автоформа может быть уродливой для сложных схем → правило: если схема сложнее
6 полей-типов, модуль рисует свою форму, но поля берёт из `settings`.
