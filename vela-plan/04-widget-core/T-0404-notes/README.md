# T-0404 — Заметки

## 1. Цель

Быстрый ввод мыслей без открытия приложений: чек-лист и текстовые заметки
прямо на рабочем столе, с поиском и без потери данных.

## 2. Функциональность

- Режим чек-листа: пункты, чекбокс, удаление, выполненное — приглушено и с
  зачёркиванием.
- Режим текста: markdown-lite (жирный, курсив, списки, ссылки автолинком),
  без HTML-инъекций.
- Быстрый ввод: `Enter` — добавить, `Ctrl+Enter` — новая строка в тексте,
  `Esc` — снять фокус.
- Сортировка: ручная (drag за ручку), выполненные вниз (опция).
- Хранение: `notes` таблица, `body` текст, `checklist_json` для чек-листа.
- Поиск по всем заметкам — из палитры команд (P7), здесь только подсветка
  при вводе в поле поиска.

## 3. Данные

```rust
pub struct Note {
    pub element_id: ElementId,
    pub title: Option<String>,
    pub body: Option<String>,
    pub checklist: Vec<ChecklistItem>, // {id, text, done, order}
}
```

- Сохранение: локальный стейт → дебаунс 600 мс → IPC `notes.save`.
- Конфликты: единственный редактор (один элемент нельзя редактировать с двух
  мониторов одновременно) — блокировка `editing_by` в сторе.
- Удаление пункта — сразу в БД (с возможностью отмены, как в T-0303).

## 5. Критерии приёмки

- **AC-1** Ввод 200 символов не даёт лагов (ввод ≤ 50 мс на символ).
- **AC-2** Заметка переживает перезапуск и крэш (дебаунс ≤ 600 мс, WAL).
- **AC-3** XSS невозможен: `<img onerror>` отображается как текст.
- **AC-4** Чекбокс не начинает drag виджета (проверка `data-no-drag`).
- **AC-5** 100 пунктов в чек-листе — прокрутка плавная (виртуализация списка).

## 7. Риски

Дебаунс + крэш = потеря последних 600 мс текста → при `blur` сохранять сразу,
плюс периодический flush раз в 5 с при активном вводе.
