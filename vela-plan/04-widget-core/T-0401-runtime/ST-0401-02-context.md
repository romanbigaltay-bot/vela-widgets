# ST-0401-02 — WidgetContext

## Цель

Всё, что нужно модулю, — в одном объекте; ничего лишнего.

## Реализация

1. `shared/widgets/context.ts`: `createContext(instance, manifest)` → `WidgetContext`.
2. `clock`: единый тикер. `ClockService` внутри: `setInterval(period, cb)` — группирует
   подписчиков по периоду (1000, 2000, 250), вызывает всех в одном тике;
   `now()` возвращает кэшированное значение тика (консистентность внутри кадра).
3. `storage`: `get/set` через `state_json` с дебаунсом 400 мс и лимитом 64 КБ.
4. `ipc`: `Proxy`, который проверяет `manifest.permissions` перед вызовом;
   запрещённые методы не существуют (`undefined`), а не падают молча.
5. `emit`: шина `EventTarget` с префиксом экземпляра; `on/off` с автоочисткой
   при unmount.
6. `log`: `ctx.log.info/warn/error` с префиксом `[core.clock#a1b2]`.
7. Объект `Object.freeze` (глубоко, кроме `ipc`-прокси).

## Критерии приёмки

- AC-1 Два виджета с периодом 1000 мс получают один тик на двоих.
- AC-2 `ctx.storage.set` не пишет в БД чаще, чем раз в 400 мс.
- AC-3 Вызов запрещённого IPC-метода даёт `undefined` и предупреждение в dev.
- AC-4 Заморозка `ctx` ловится тестом.

## Тест-план

TC-0401-02 + юнит на группировку тиков и дебаунс storage.

## Риски

Общий тикер при долгой задаче одного подписчика задерживает остальных →
обёртка с `try/catch` и замером длительности, предупреждение при > 8 мс.
