# T-0401 — Рантайм виджетов

## 1. Цель

Реализовать контракт `00-conventions/09-widget-spec.md`: модуль объявляет
манифест, получает контекст, живёт по lifecycle, не может уронить холст.

## 2. Реестр

```ts
// Регистрация — статическая, на этапе сборки, без динамической загрузки в v1
const registry = new WidgetRegistry();
registry.register(coreClock);
registry.register(coreNotes);
// манифесты доступны Rust через IPC widget.manifest_list (для валидации settings)
```

- Модули — отдельные папки `features/widgets/core/clock/{manifest.ts, Clock.tsx, index.ts}`.
- Реестр строит индекс по `id`, проверяет уникальность и совместимость версии
  контракта (`apiVersion: 1`).
- Манифест отдаётся в Rust при старте, чтобы схема настроек валидировалась
  в одном месте с БД.

## 3. Изоляция и устойчивость

- Каждый виджет обёрнут в `WidgetBoundary` (`ErrorBoundary` + `Suspense`):
  при исключении — плашка «Модуль остановлен» с кнопкой «Перезапустить» и
  кодом ошибки; остальной холст жив.
- Ограничения контекста: `ctx` — объект с замороженными полями, без доступа к
  `window`, `document`, камере.
- Права проверяются на каждом вызове `ctx.ipc.*`: нет права — `PermissionDenied`.
- Бюджет времени: `onMount` обязан завершиться за 50 мс (в dev — предупреждение
  при превышении).

## 4. Видимость и энергия

```
visible    → onVisibilityChange(true),  тикеры работают
occluded   → (перекрыт оверлеем) тикеры на паузе, рендер 0 fps
offscreen  → размонтирован визуально, состояние сохранено
suspended  → (сон системы) всё на паузе, catch-up при пробуждении
```

Определение `visible/offscreen` — по пересечению с вьюпортом (из T-0301-03).
`occluded` — когда поверхность B перекрыта оверлеем C или fullscreen-приложением.

## 5. Службы контекста

| Служба | Что даёт |
|---|---|
| `clock` | `now()`, `setInterval(ms, cb)`, `setTimeout`, единый тик на всех; инжектируется для тестов |
| `storage` | key-value в `elements.state_json` (лимит 64 КБ), с дебаунсом записи |
| `ipc` | типизированный API, отфильтрованный по правам |
| `theme` | текущая тема, подписка |
| `emit` | шина между виджетами (`'timer.finished'` → слушает плеер) |
| `log` | префиксный логгер с кольцевым буфером |

**Единый clock-сервис** — принципиально: 9 виджетов не должны держать 9
`setInterval`. Один тик раз в секунду (и отдельный rAF для анимаций), подписчики
получают вызов, если им нужно.

## 7. Критерии приёмки

- **AC-1** Виджет с `throw` в рендере не ломает холст; плашка с перезапуском.
- **AC-2** Виджет без права `net:http` получает `PermissionDenied` при вызове.
- **AC-3** 50 циклов mount/unmount: `performance.memory` стабилен в пределах 5 %.
- **AC-4** Один `setInterval` на приложение (проверка счётчиком в dev).
- **AC-5** Виджет вне вьюпорта: тикеры не выполняются (счётчик вызовов = 0).
- **AC-6** `ctx` заморожен: попытка записи в dev даёт ошибку.

## 9. Риски

- Единый clock может стать узким местом при 20 виджетах → батчинг по 100 мс окнам.
- Заморозка `ctx` ломает некоторые удобные паттерны → в документации контракта
  явные примеры «как правильно».
