# T-0302 — Модель раскладки

## 1. Цель

Единая модель элемента и раскладки, которая одинаково понимается Rust, UI и
БД, с сохранением, восстановлением и миграцией.

## 2. Модель элемента

```rust
pub struct Element {
    pub id: ElementId,
    pub kind: ElementKind,          // Widget | Pin | Note | Ink | Group
    pub widget_id: Option<WidgetId>, // 'core.clock'
    pub monitor_id: MonitorId,
    pub profile_id: Option<ProfileId>, // None = во всех профилях
    pub frame: Rect,                // мировые координаты, CSS px
    pub z: i32,
    pub rotation: f32,              // 0 по умолчанию, для pin/ink
    pub settings: serde_json::Value,
    pub state: serde_json::Value,   // нестабильные данные модуля
    pub created_at: i64,
    pub updated_at: i64,
}
```

Правила:
- `frame` — мировые координаты; экранные получаются камерой. Элемент не знает
  про камеру.
- `settings` валидируется JSON-схемой манифеста; `state` — свободная зона модуля,
  размер ограничен 64 КБ.
- `profile_id = None` значит «виден везде»; иначе — только в указанном профиле.

## 3. Патчи и транзакции

```rust
pub struct ElementPatch {
    pub id: ElementId,
    pub op: PatchOp,          // Upsert | Move | Resize | Remove | ZOrder | Settings
    pub frame: Option<Rect>,
    pub z: Option<i32>,
    pub settings: Option<serde_json::Value>,
}
ElementsRepo::apply_patch(Vec<ElementPatch>) -> Result<LayoutSnapshot>
```

- Одна транзакция на жест (не на кадр).
- Ответ — полный снапшот раскладки монитора, чтобы другие поверхности
  применили его без второго запроса.
- Конфликты (две поверхности двигают один элемент) решаются по `updated_at`
  + приоритет владельца: последний завершённый жест побеждает, но с `revision`
  счётчиком, чтобы UI мог откатить своё оптимистичное состояние.

## 4. Восстановление при изменениях мониторов

- При старте: элементы привязываются к монитору по `monitors` таблице (сохранённая
  геометрия). Если монитор не найден — его элементы переносятся в видимую область
  основного монитора со сдвигом «каскадом» и пометкой `orphaned`.
- `orphaned` элементы показываются в специальной зоне (правый нижний угол,
  приглушённые) до перемещения пользователем.
- Формула каскада: `x += 48 * (i % 8)`, `y += 48 * floor(i / 8)`.

## 6. Критерии приёмки

- **AC-1** Перетаскивание 10 элементов подряд даёт 10 транзакций, не 600.
- **AC-2** Перезапуск возвращает всё точно (позиция ±0 px, z, настройки).
- **AC-3** Патч с невалидным `settings` отклоняется целиком, БД не меняется.
- **AC-4** Отключение монитора переносит его элементы без потерь, они помечены
  `orphaned` и доступны.
- **AC-5** Оптимистичное обновление откатывается при ошибке IPC (тост + откат).

## 8. Риски

- Дрейф оптимистичного состояния при быстрых жестах → `revision` и принудительный
  snapshot-refresh после каждого apply_patch.
- `state_json` может расти (история) → лимит 64 КБ + предупреждение в dev.
