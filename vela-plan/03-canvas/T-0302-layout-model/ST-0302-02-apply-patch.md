# ST-0302-02 — IPC `layout.*`

## Цель

Все изменения раскладки идут через одну транзакционную команду с ответом-снапшотом.

## Реализация

1. Команды: `layout.get {monitor, profile?}` → `LayoutSnapshot`;
   `layout.apply_patch {monitor, patches, revision}` → `LayoutSnapshot`;
   `layout.set_camera {monitor, camera}`; `layout.reset {monitor}`.
2. `apply_patch`: валидация всех патчей → одна транзакция → новый снапшот →
   событие `layout.changed {monitor, revision, snapshot}` другим поверхностям
   (не отправителю).
3. `revision` монотонно растёт на каждый коммит; UI отбрасывает снапшоты
   с меньшей ревизией.
4. Ограничения: ≤ 200 патчей за вызов, ≤ 64 КБ payload.
5. Ошибка в любом патче → откат всего, ответ `InvalidInput` с индексом патча.

## Критерии приёмки

- AC-1 50 патчей ≤ 15 мс (замер в интеграционном тесте).
- AC-2 Отправитель не получает собственное событие (нет лишнего рендера).
- AC-3 Снапшот с меньшей `revision` игнорируется UI.

## Тест-план

TC-0302-01, TC-0302-03; тест на конкурентные патчи из двух «мониторов».

## Риски

Широковещательная рассылка снапшота на каждый жест — трафик; при > 2 мониторах
оптимизировать до дельт (вынести в P8 при необходимости).
