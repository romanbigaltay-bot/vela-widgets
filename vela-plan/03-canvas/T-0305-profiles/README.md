# T-0305 — Профили

## 1. Цель

Один клик меняет и раскладку, и сцену, и видимость элементов — без перезапуска
и без потери состояния.

## 2. Модель профиля

```rust
pub struct Profile {
    pub id: ProfileId,
    pub name: String,
    pub scene: SceneConfig,      // {kind: 'photo'|'video'|'scene2d'|'scene3d', source, params}
    pub visible_widgets: Vec<WidgetId>, // фильтр видимости поверх общей раскладки
    pub camera: Option<Camera>,  // своя камера на профиль
    pub rules: ProfileRules,     // автопереключение по времени/приложению (P7)
}
```

- Элементы **не пересоздаются** при смене профиля: меняется только видимость
  (`profile_id` + `visible_widgets`).
- Переход: crossfade сцены 400 мс, элементы — `opacity/scale` 200 мс.
- Активный профиль — в `settings.active_profile`, события `profile.changed`.

## 3. Атомарность

Переключение — одна IPC-команда `profile.activate {id}`:
1. Проверка: профиль существует, сцена доступна.
2. Пауза таймеров виджетов, которые станут невидимыми.
3. Смена сцены (A), затем раскладки (B).
4. Ack: `profile.activated {id, tookMs}`.
Ошибка на любом шаге → откат к предыдущему профилю + тост.

## 5. Критерии приёмки

- **AC-1** Переключение ≤ 450 мс, без белой вспышки.
- **AC-2** Скрытые виджеты останавливают таймеры (0 fps).
- **AC-3** Возврат к профилю восстанавливает и раскладку, и камеру.
- **AC-4** Ошибка сцены (файл удалён) не ломает профиль: остаётся прежний.
- **AC-5** Профили редактируются: создание, переименование, удаление (кроме
  последнего), смена порядка.

## 7. Риски

Профили легко превращаются в «вторую раскладку» и путают пользователя →
в UI явно: профиль = «набор виджетов + сцена», позиции общие, если не включён
`independent_layout` (опция P8).
