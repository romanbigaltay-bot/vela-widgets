# ST-0305-01 — Модель профиля

## Цель

Профиль как данные, с валидацией и CRUD без побочных эффектов.

## Реализация

1. `vela-core::profile`: `Profile`, `SceneConfig`, `ProfileRules`, `visible_widgets`.
2. `ProfilesRepo`: `list`, `get`, `upsert`, `delete` (запрет удаления последнего),
   `reorder` (sort).
3. IPC: `profile.list`, `profile.upsert`, `profile.delete`, `profile.reorder`,
   `profile.activate` (логика в ST-0305-02).
4. Значения по умолчанию при первом запуске: «Работа» (фото + часы/календарь/заметки),
   «Вечер» (тёмная сцена + часы/плеер), «Игра» (без виджетов, сцена на паузе).
5. Валидация `SceneConfig`: `kind` из перечисления, `source` — существующий
   файл/URL из allow-list, `params` по схеме.

## Критерии приёмки

- AC-1 Удалить последний профиль нельзя (`InvalidInput`).
- AC-2 `reorder` сохраняет порядок и отражается в трее.
- AC-3 Дефолтные профили создаются только при пустой таблице.

## Тест-план

Интеграционные тесты CRUD на временной БД.

## Риски

Пользователь может удалить профиль, на который ссылаются элементы с
`profile_id` → поведение: элементы становятся `profile_id = NULL` (видны везде),
с предупреждением.
