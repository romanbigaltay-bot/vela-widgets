# ST-0301-04 — Рендер-цикл

## Цель

Ноль кадров, когда ничего не меняется. Это главный вклад в бюджет CPU idle.

## Реализация

1. `shared/lib/raf.ts`: `useFrameLoop(active: boolean, cb)` — запускает rAF
   только при `active`; `active` = есть жест ИЛИ есть анимация ИЛИ изменилась
   камера/раскладка.
2. Глобальный `FrameScheduler`: очередь задач с приоритетом (сцена, стекло,
   элементы); пропускает задачи с нулевыми изменениями.
3. `document.visibilitychange` и `LifecycleService.suspended` → цикл стопится.
4. Счётчик кадров в dev-панели (для AC-4 гейта).
5. Правило: ни один компонент не вызывает `requestAnimationFrame` напрямую —
   только через `useFrameLoop`.

## Критерии приёмки

- AC-1 Idle 10 с: 0 кадров (счётчик).
- AC-2 Во время drag — 60 fps (или частота монитора).
- AC-3 После `pointerup` анимация завершается и цикл останавливается ≤ 300 мс.

## Тест-план

TC-0301-04, автотест счётчика кадров через dev-API.

## Риски

Забытый `active = true` даёт вечный цикл → линт-правило: `useFrameLoop` требует
`active` из стора, не литерал `true` (проверяется ESLint custom rule).
