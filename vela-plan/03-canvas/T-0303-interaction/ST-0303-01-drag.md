# ST-0303-01 — Перетаскивание

## Цель

Прямое манипулирование без задержек и без побочных эффектов.

## Реализация

1. `useDrag(el)`: `pointerdown` (не на интерактивном потомке) →
   `setPointerCapture` → `pointermove` (rAF-батчинг) → `pointerup`.
2. Порог 3 px: до него событие считается кликом (выделение).
3. Дельта делится на `camera.scale` → мировые координаты; элемент двигается
   через `translate3d(dx, dy, 0)` относительно исходной позиции.
4. `Esc` → `cancelGesture()`, `pointercancel` → тоже; состояние возвращается
   из снимка `beginGesture`.
5. `pointerup` → `commitGesture()` (IPC), тост при ошибке.
6. Интерактивные потомки (input/button/checkbox/[data-no-drag]) игнорируются.

## Критерии приёмки

- AC-1 Задержка ≤ 1 кадр; нет «отставания» при быстром движении.
- AC-2 `Esc` отменяет без записи в БД.
- AC-3 Клик по чекбоксу не начинает перетаскивание.
- AC-4 `pointercancel` (выход за экран) не оставляет «залипший» элемент.

## Тест-план

TC-0303-02; ручной тест на 144 Гц.

## Риски

`setPointerCapture` на элементе внутри трансформированного контейнера даёт
смещение координат на некоторых версиях Chromium → использовать
`e.clientX/Y` и пересчёт через камеру, не `offsetX`.
