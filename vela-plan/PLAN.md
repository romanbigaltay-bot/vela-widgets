# Основной план

## 1. Продукт в одном абзаце

Vela — фоновый слой Windows 11, который заменяет рабочий стол: вместо обоев
живая сцена (фото, видео, 2D/3D, игра), поверх неё — бесконечный холст с
виджетами (часы, таймер, cron, календарь, заметки, захват экрана, рисование,
система, погода, плеер). Интерфейс — тёмный или светлый, без засечек, с
холодным акцентом, тонкими тенями, едва заметной подсветкой и размытым стеклом
только на панелях-контейнерах. Приложение стартует вместе с Windows по желанию,
живёт в трее, не мешает играм и не жжёт батарею.

## 2. Принципы

1. **Сначала контракт, потом код.** Любой межслойный интерфейс описан в
   `01-foundations/T-0102` до начала реализации потребителей.
2. **Один владелец состояния.** Раскладка — в SQLite, рантайм-состояние — в
   Zustand, окна — в Rust. Дублирование состояния запрещено.
3. **Энергия — функция продукта.** Ничего не анимируется, если на это нет
   причины: idle = 0 кадров, батарея = 30 fps, fullscreen-игра = пауза.
4. **Деградация вместо падения.** WorkerW не найден, RDP, смена драйвера,
   Explorer перезапустился — приложение остаётся работоспособным в упрощённом
   виде и говорит об этом пользователю.
5. **Честное стекло.** Размытие считается из реальной сцены, а не имитируется
   полупрозрачной плашкой. Если сцена недоступна — панель становится матовой,
   но не врёт.
6. **Никакой телеметрии по умолчанию.** Сеть только по явному действию
   пользователя (погода, ICS, тикер).

## 3. Архитектура: три поверхности

| Слой | Окно | Что рисует | Ввод |
|---|---|---|---|
| **A — Scene** | WebView2 (WebGL2), припарентен к `WorkerW` | фото/видео/2D-3D/игра, полное качество | нет, click-through |
| **B — UI** | WebView2, прозрачное, `WS_EX_NOACTIVATE`, над иконками | холст, виджеты, панели, стекло | да, по правилам режимов |
| **C — Overlay** | WebView2, top-most на время вызова | палитра команд, аннотации, настройки | да |

**Ревизия относительно первого эскиза.** В эскизе предполагалось, что слой B
напрямую берёт текстуру сцены A. Технически это невозможно: A и B — разные
WebView2, у каждого свой D3D-контекст, общая текстура между ними не шарится без
`Windows.Graphics.Capture` с задержкой 1–2 кадра и стоимостью ~3–5 мс на кадр.
Поэтому принято решение **«blur mirror»**: слой B содержит собственную
уменьшенную копию сцены (0.25 линейного разрешения, 20–30 fps, только пока на
экране есть стеклянная панель) и размывает её в шейдере. Стоимость — доли
миллисекунды, содержимое совпадает попиксельно по композиции, а не по кадру.
Обоснование и альтернативы — `ADR-0003`.

**Про иконки.** Слой A живёт под иконками (WorkerW) — иконки остаются видны.
Слой B живёт над иконками, поэтому стеклянные панели размывают в том числе
иконки под собой. Это осознанный компромисс; альтернатива «спрятать иконки»
доступна тумблером. Подробно — `ADR-0004`.

## 4. Целевые метрики (NFR)

Полная версия и методика измерения — `00-conventions/06-nfr-budget.md`.

| Метрика | Цель | Порог провала |
|---|---|---|
| Память, 9 виджетов + фото-сцена, 1080p | ≤ 420 МБ | > 600 МБ |
| CPU idle (нет анимаций, окно не в фокусе) | ≤ 1.0 % | > 2.5 % |
| CPU активный холст (перетаскивание) | ≤ 12 % | > 20 % |
| Сцена 1440p, 3 слоя, 60 fps | стабильно 60 | < 45 |
| Стоимость стекла, панель 400×300 | ≤ 0.8 мс/кадр | > 2 мс |
| Холодный старт до видимых виджетов | ≤ 1.5 с | > 3 с |
| Задержка ввода виджета (клик → отклик) | ≤ 16 мс | > 50 мс |
| Установленный размер | ≤ 45 МБ | > 90 МБ |
| Crash-free sessions (7 дней) | ≥ 99.5 % | < 98 % |

## 6. Граф зависимостей

```
P1 ──► P2 ──► P3 ──► P4 ──┬──► P5 ──┐
                          ├──► P7 ──┼──► P8
P1 ──────────────────────► P6 ───────┘
```

- P5 и P6 зависят от P3/P4 (им нужен холст и модель элементов), но не друг от друга.
- P7 требует P4 (рантайм) и P2 (планировщик для cron).
- P8 трогает всё, поэтому идёт последним; при сжатых сроках начинается
  параллельно с P7 силами второго разработчика.

## 8. Дисциплина плана

- Задача берётся в работу только со статусом `ready`: цель, критерии приёмки и
  тест-план заполнены, зависимости закрыты.
- Один PR = одна подзадача (или несколько строго одной задачи). В описании PR —
  идентификатор `ST-...`.
- Обнаруженный объём, не покрытый планом, не «доделывается молча»: заводится
  новая подзадача, план правится в том же PR.
- Изменение архитектурного решения = новый или переписанный ADR, ссылка из
  затронутых задач, отметка в разделе «Ревизии» этого файла.
- Раз в этап — сверка фактических часов с оценкой; расхождение > 50 % разбирается
  на предмет неверной декомпозиции, а не «медленного разработчика».
