# P1 — Каркас и контракты

**Цель этапа:** получить пустое, но полностью собранное приложение, в котором
все межслойные интерфейсы, схема БД и дизайн-токены уже зафиксированы. Дальше
этапы пишут поведение, а не скелет.

**Оценка:** 4 дня. **Gate:** G1.

| ID | Задача | Приоритет | Дней | Владелец | Зависит от |
|---|---|---|---|---|---|
| T-0101 | Репозиторий, workspace, toolchain, CI | P0 | 1.0 | оба | — |
| T-0102 | Контракты IPC и генерация TS-типов | P0 | 1.0 | rust | T-0101 |
| T-0103 | Дизайн-токены, темы, ThemeService | P0 | 1.0 | ui | T-0101 |
| T-0104 | SQLite-схема, миграции, репозитории | P0 | 1.0 | rust | T-0101 |

## Порядок выполнения

```
T-0101 ──┬──► T-0102 ──┐
         ├──► T-0103 ──┼──► G1
         └──► T-0104 ──┘
```
T-0102 и T-0104 можно вести параллельно: схема БД не зависит от IPC-типов,
но оба используют структуры из `vela-core`, которые появляются в T-0101.

## Критерии выхода (G1)

- [ ] `cargo run -p vela` открывает пустое прозрачное окно 800×600.
- [ ] `pnpm dev` показывает пустую страницу с правильными токенами и шрифтом.
- [ ] `pnpm ipc:gen` перегенерирует TS-типы, дифф в CI пустой.
- [ ] `cargo test` и `pnpm test` — зелёные, покрытие ≥ 60 % по новым модулям.
- [ ] CI-пайплайн из `05-testing.md` проходит на пустом проекте.
- [ ] БД создаётся при первом старте, миграция с нуля идемпотентна.
- [ ] Переключение `data-theme` меняет все токены без вспышек.
- [ ] README репозитория объясняет запуск за 3 команды.

## Что НЕ входит

Реальные окна-поверхности, холст, виджеты, сцена, захват. Только каркас и
контракты. Любая попытка «заодно сделать часы» здесь — нарушение этапа.
