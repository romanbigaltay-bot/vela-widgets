# T-0704 — Планировщик

## 1. Цель

Мощный, но не страшный планировщик: действия по расписанию, с понятным
предпросмотром «когда это сработает» и надёжным исполнением, независимым от UI.

## 2. Действия (v1)

| Действие | Параметры |
|---|---|
| `profile.activate` | id профиля |
| `scene.set` | источник сцены |
| `notify` | заголовок, текст |
| `run.command` | путь + аргументы (только из allow-list, подтверждение) |
| `app.launch` | путь/URI (только `http(s)`, `ms-settings:`) |
| `capture.screenshot` | режим, папка |
| `widget.toggle` | id виджета, видимость |

- `run.command` — самое опасное: требует явного подтверждения при создании,
  хранится с хешем, при изменении бинаря — блокируется.

## 3. Расписание

- Формат: cron-выражение (`0 9 * * 1-5`) + человекочитаемый предпросмотр
  («по будням в 09:00», «следующее: пн, 09:00»).
- Условия (опции): только на сети / только на батарее не выполнять /
  только при активном профиле X / не выполнять, если пользователь активен
  (idle > 5 мин).
- Catch-up: если срабатывание пропущено (сон) — выполнить один раз при старте,
  если включено.

## 4. Исполнение

- Поток `vela-cron`: раз в 20 с сверяет `next_fire_at <= now`.
- Идемпотентность: `(job_id, fire_at)` в `cron_runs` — уникальный индекс;
  повторная попытка не дублирует.
- Лог: `cron_runs {job_id, fire_at, status: 'ok'|'failed'|'skipped', error, ms}`,
  последние 200 в UI.
- Сбой действия → `failed` + тост, не ретраится автоматически (кроме `notify`).

## 5. Состав подзадач

## 6. Критерии приёмки

- **AC-1** Парсер: 30 выражений, `next_fire_at` корректен (включая `*/5`, `1-5`, `L`).
- **AC-2** Срабатывание в пределах ±2 с от расчётного времени.
- **AC-3** Пропуск из-за сна → одно выполнение при старте (если catch-up).
- **AC-4** `(job_id, fire_at)` не даёт дублей даже при двойном тике.
- **AC-5** Предпросмотр в UI совпадает с реальным срабатыванием.
- **AC-6** `run.command` без подтверждения не создаётся.
