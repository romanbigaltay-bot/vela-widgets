# ST-0704-02 — Поток планировщика

## Цель

Срабатывания не зависят от UI, не дублируются, не теряются.

## Реализация

1. Поток `cron` с тиком 20 с: `SELECT * FROM cron_jobs WHERE enabled AND next_fire_at <= now`.
2. Для каждого: `INSERT INTO cron_runs(job_id, fire_at) ... ON CONFLICT DO NOTHING`
   → если вставка произошла, выполняем действие; иначе пропускаем (уже было).
3. После выполнения: `next_fire_at = next_fire_at(schedule, now)`, `last_fire_at`.
4. Catch-up при старте: если `next_fire_at < now - 60s` и `catch_up` — выполнить
   один раз с фактическим `fire_at`, затем пересчитать.
5. Ошибки действий: `status = 'failed'`, лог, событие `cron.failed` (тост).
6. Остановка: по `LifecycleService::Exiting` — дождаться текущего действия (≤ 2 с).

## Критерии приёмки

- AC-1 ±2 с от расчётного времени.
- AC-2 Нет дублей при двух одновременных тиках (тест с искусственным сдвигом).
- AC-3 Catch-up одно выполнение, не N.
- AC-4 Остановка ≤ 2 с.

## Тест-план

TC-0704-02, TC-0704-03.

## Риски

Действие может «зависнуть» (внешний процесс) → таймаут 30 с на действие, статус
`failed`, поток не блокируется навсегда.
