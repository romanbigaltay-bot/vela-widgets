# Vela — план разработки

Рабочее имя продукта: **Vela**. Виджетный слой рабочего стола для Windows 11:
живой фон (фото / видео / 2D-3D сцена / игра), бесконечный холст с виджетами,
утончённый минималистичный интерфейс со стеклянными панелями.

Этот каталог — единственный источник истины по объёму работ. Код живёт отдельно,
план живёт здесь и обновляется вместе с кодом (см. «Дисциплина плана» в PLAN.md).

## Как читать

1. **PLAN.md** — обзор: этапы, gates, сроки, зависимости, сквозные решения.
   Начинать всегда с него.
2. **`NN-<этап>/README.md`** — план этапа: состав задач, порядок, критерии выхода.
3. **`NN-<этап>/T-XXXX-<слаг>/README.md`** — ТЗ на задачу: цель, объём,
   технические решения, контракты, критерии приёмки, тест-план, риски.
4. **`NN-<этап>/T-XXXX-<слаг>/ST-XXXX-NN-<слаг>.md`** — ТЗ на подзадачу:
   что делаем, как, какие файлы появляются, как проверить. Это атомарная
   единица работы: одна подзадача ≈ один PR.

Глубина всегда одинаковая: этап → задача → подзадача. Ниже подзадачи
декомпозиция не идёт — если подзадача не влезает в один PR, значит она
описана неверно и её нужно разделить на уровне файлов подзадач.

## Состав каталога

| Путь | Что внутри |
|---|---|
| `PLAN.md` | этапы, gates, график, зависимости, ревизии архитектуры |
| `INDEX.md` | плоский индекс всех задач и подзадач (генерируется) |
| `manifest.json` | машиночитаемый реестр задач: id, этап, оценка, зависимости |
| `00-conventions/` | правила: термины, идентификаторы, DoD, ADR, тесты, NFR, риски |
| `01-foundations/` | P1 — каркас репозитория, контракты, токены, ADR |
| `02-shell/` | P2 — окна и поверхности, слой рабочего стола, автозапуск, темы |
| `03-canvas/` | P3 — бесконечный холст, раскладка, режимы ввода, стекло |

| `08-release/` | P8 — производительность, мультимонитор, доступность, установщик |

## Соглашения в двух строках

- Идентификаторы неизменяемы: `P<n>`, `T-<этап><номер>`, `ST-<задача>-<номер>`,
  `ADR-<номер>`, `R-<номер>` (риск), `OQ-<номер>` (открытый вопрос). Задачи не
  перенумеровываются при переносе сроков — только меняется статус.
- Каждая задача имеет приоритет (`P0` блокирует этап, `P1` нужен для релиза,
  `P2` улучшение) и оценку в днях. Оценка — не обещание, а размер.
- Статус задачи ведётся в её README строкой `status:`: `draft → ready → in-progress
  → review → done → cut`. `cut` — сознательно выкинуто, с причиной.

## Роли

Один разработчик может закрыть весь план; разделение ниже — для параллельной
работы двух человек.

- **Rust/Platform** — окна, WorkerW, DWM, автозапуск, БД, планировщик, захват.
- **UI/Rendering** — React-слои, холст, WebGL-сцена, стекло, дизайн-система.

## Чего в этом плане нет

Маркетинга, монетизации, облачной синхронизации, мобильной версии, macOS/Linux.
Всё это вынесено за границу текущего объёма (см. `PLAN.md`, раздел «Вне объёма»).
