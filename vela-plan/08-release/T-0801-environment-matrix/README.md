# T-0801 — Матрица окружений

## 1. Цель

Пройти все конфигурации, где приложение обычно ломается: два монитора с разным
DPI, отключение экрана, RDP, смена разрешения на ходу.

## 2. Матрица

| # | Конфигурация | Что проверяем |
|---|---|---|
| M1 | 1×1080p@100 % | базовая |
| M2 | 1×4K@150 % | чёткость текста, геометрия сцены |
| M3 | 2×(1440p@100 % + 1080p@125 %) | независимые вьюпорты, стекло |
| M4 | 2×(4K@200 % + 1080p@100 %) | экстремальная разница DPI |
| M5 | Отключение второго монитора | orphaned, раскладка |
| M6 | Подключение монитора | появление пустого вьюпорта, без дублей |
| M7 | Смена разрешения на ходу | пересчёт, без артефактов |
| M8 | RDP-сессия | деградация сцены, работа UI |
| M9 | Проектор (только второй экран) | primary смена |
| M10 | Виртуальная машина (нет GPU) | фолбэк на матовое стекло, fps |

## 3. Исправления, ожидаемые по опыту

- Стекло на M3/M4 может «съезжать» на несколько пикселей → коррекция по
  `devicePixelRatio` каждого монитора.
- При M5 элементы могут «уехать» за границы → уже решено в ST-0302-04, здесь
  проверка в реальности.
- RDP не поддерживает WorkerW → фолбэк, уже есть, здесь проверка что UI не
  пытается рисовать сцену.
- VM без GPU: WebGL может быть software → уровень качества 1 + матовое стекло.

## 5. Критерии приёмки

- **AC-1** Все 10 конфигураций пройдены, результаты в таблице с скриншотами.
- **AC-2** Нет элементов за пределами видимой области ни в одной конфигурации.
- **AC-3** Текст чёткий на 100/125/150/200 % (проверка скриншотами).
- **AC-4** RDP и VM: приложение работает, сцена деградирует, пользователь уведомлён.

## 6. Тест-план

Ручной прогон по матрице + автоматические проверки геометрии (как TC-0202-05)
на каждой конфигурации.

## 7. Риски

Нет доступа к железу для M4/M9 → аренда VM/удалённый стенд, заложить в план
заранее.
