# T-0802 — Производительность и soak

## 1. Цель

Подтвердить бюджеты `06-nfr-budget.md` цифрами на реальной сборке и найти
утечки до пользователя.

## 2. Прогоны

| Прогон | Длительность | Что смотрим |
|---|---|---|
| Idle (нет анимаций) | 60 мин | CPU, 0 fps, память |
| Активный холст | 30 мин | CPU при pan/zoom, fps |
| Видео-фон | 120 мин | CPU/GPU, память, пропуски кадров |
| Скриншоты ×50 | 15 мин | память, хендлы |
| Смена профилей ×100 | 15 мин | память, утечки текстур |
| Soak общий | 8 ч | всё вместе + деградация |

## 3. Инструменты

- `bench/memory.ps1`, `bench/cpu.ps1`, `bench/soak.ps1` — уже есть с P1.
- Снимки heap: DevTools (UI) + `dotnet-counters`-подобный для WebView2 не
  применим, поэтому полагаемся на `Private Working Set` и число процессов.
- Профиль GPU: встроенный счётчик сцены.

## 4. Состав подзадач

| ID | Подзадача | Дней |
|---|---|---|
| ST-0802-01 | Прогоны и таблица факт/план | 0.5 |
| ST-0802-02 | Устранение найденных утечек | 0.5 |

## 5. Критерии приёмки

- **AC-1** Все метрики в бюджете или с обоснованным отклонением.
- **AC-2** Память за 8 ч растёт ≤ 5 %.
- **AC-3** Нет роста числа процессов WebView2.
- **AC-4** Отчёт с таблицей факт/план приложен к G8.

## 6. Тест-план

Сами прогоны + сравнение с бюджетом.

## 7. Риски

Soak на рабочей машине мешает работе → отдельный стенд или ночной прогон.
