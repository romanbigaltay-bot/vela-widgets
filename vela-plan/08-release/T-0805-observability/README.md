# T-0805 — Наблюдаемость

## 1. Цель

Когда что-то ломается на чужой машине, у нас есть данные для ответа — и при
этом мы не собираем телеметрию.

## 2. Логи

- `tracing` в Rust: файл `%LOCALAPPDATA%\Vela\logs\vela-YYYY-MM-DD.log`,
  ротация 7 дней, лимит 10 МБ.
- Уровни: `info` по умолчанию, `debug` — по флагу `--debug` или настройке.
- UI-ошибки: кольцевой буфер 200 записей → при инциденте попадают в лог.
- Приватность: не логировать содержимое заметок, буфера, URL календаря (только домен).

## 3. Диагностика

Кнопка «Собрать отчёт» в настройках → zip:
`version.txt` (версии приложения, WebView2, Windows, GPU), `logs/`,
`surfaces.json` (состояние окон), `metrics.json` (последние метрики),
`config-redacted.json` (настройки без приватного), `dumps/` (опционально).
- Пользователь видит список файлов перед отправкой.
- Никакой автоматической отправки.

## 4. Crash-репорты

- Не отправляем автоматически. При падении — запись в лог + при следующем
  запуске предложение «Отправить отчёт?» (с превью содержимого).
- Локальные дампы (`%LOCALAPPDATA%\Vela\crashes`), лимит 5, старые удаляются.

## 6. Критерии приёмки

- **AC-1** Логи не растут бесконечно (ротация работает).
- **AC-2** Отчёт содержит версии и состояние, но не приватные данные (тест с
  заметкой «секрет» — в отчёте её нет).
- **AC-3** При падении отчёт предлагается при следующем старте.
- **AC-4** Ни одного сетевого запроса без действия пользователя (проверка
  сниффером за 1 час работы).

## 7. Тест-план

| ID | Проверка |
|---|---|
| TC-0805-01 | Ротация: 8 дней логов → 7 файлов |
| TC-0805-02 | Редакция: заметка «секрет» отсутствует в отчёте |
| TC-0805-03 | Сниффер: 1 час, только запросы погоды/календаря по расписанию |

## 8. Риски

Логи могут содержать приватное по неосторожности → правило «не логировать
пользовательские данные», проверяется в ревью и тестом.
