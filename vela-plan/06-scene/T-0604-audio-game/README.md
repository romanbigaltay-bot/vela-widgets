# T-0604 — Аудио и игра

## 1. Цель

Сцена реагирует на звук системы (визуализатор как фон) и готова принять
интерактивную 2D-игру как источник сцены.

## 2. Аудиореакция

- Захват системного звука: WASAPI loopback (Rust) → 40 значений спектра
  (FFT 1024, 20–30 Гц в секунду) → `scene.audio_frame` событие.
- Публикация не чаще 30 fps, только если сцена подписана на аудио.
- В шейдере — 8 агрегированных полос (uniform), в виджете-визуализаторе —
  до 32 полос.
- Отключено по умолчанию, требует явного включения (микрофон/звук — приватность).
- Работает при отсутствии устройства (тишина = нули, без ошибок).

## 3. Игра как сцена (каркас)

- `canvas2d` источник: `<canvas>` в A, который рендерит модуль-игра по контракту
  `SceneGame { init(ctx), frame(dt), input(event) }`.
- Ввод: события мыши приходят из B (там есть хит-тест) через IPC, координаты
  пересчитываются камерой. Игра не имеет прямого доступа к DOM.
- Ограничения: 30 fps бюджет, пауза при невидимости, `requestAnimationFrame`
  только при активной игре.
- В v1 — только каркас + демо-игра (клик по частицам), без полноценных игр.

## 5. Критерии приёмки

- **AC-1** Аудиореакция: задержка ≤ 60 мс между звуком и реакцией.
- **AC-2** CPU на loopback+FFT ≤ 1.5 %.
- **AC-3** Выключено по умолчанию; включение — из настроек с пояснением.
- **AC-4** При отсутствии аудиоустройства — нули, без ошибок в консоли.
- **AC-5** Игра-каркас: ввод доходит, координаты верны при зуме холста.

смены устройства (пересоздать клиент).
