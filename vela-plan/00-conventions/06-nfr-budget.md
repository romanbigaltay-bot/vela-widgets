# 06 — Бюджеты производительности

## Методика замера

- Стенд: Windows 11 24H2, Ryzen 5 5600 / 16 ГБ / GTX 1650, 1440p@100 %, питание от сети.
- Память: `Private Working Set` процесса Vela + всех его WebView2-процессов
  (`Get-Process | Where-Object {$_.ProcessName -match 'vela|msedgewebview2'}`).
- CPU: среднее за 60 с в трёх состояниях (idle / активный / перетаскивание),
  замер через `typeperf "\Process(Vela)\%% Processor Time"`.
- fps сцены: счётчик внутри сцены (WebGL `EXT_disjoint_timer_query` + скользящее окно 2 с).
- Стоимость стекла: таймер вокруг прохода blur в рендер-цикле, среднее по 300 кадрам.

| Метрика | Бюджет | Жёсткий предел | Как ловить регресс |

| CPU idle (нет анимаций) | 1.0 % | 2.5 % | `bench/cpu.ps1`, 60 с |

| Баттарея: сцена выключена | 3.5 %/ч | 6 %/ч | 2-часовой прогон |

## Правила при превышении

1. Сначала измеряется, потом оптимизируется — без профиля правок не делаем.
2. Бюджет нарушен → задача не закрывается; создаётся подзадача на оптимизацию
   с обязательным профилем до/после в PR.
3. Три подряд нарушения в одном этапе → ревизия архитектуры (ADR), а не латание.

## Инструменты

`bench/` появится в T-0802 (P8). До этого замеры NFR **не воспроизводимы**:
скриптов `memory.ps1`, `cpu.ps1`, `startup.ps1`, `soak.ps1`,
`glass_bench.rs` в репозитории нет. Каждый скрипт должен писать CSV в
`bench/out/`; CI хранит артефакты 90 дней.
