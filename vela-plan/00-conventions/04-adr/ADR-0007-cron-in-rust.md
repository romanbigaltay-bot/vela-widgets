# ADR-0007 — Планировщик cron в Rust, не в UI

**Статус:** принято

## Контекст

Cron-модуль должен срабатывать даже когда UI-поверхность не отрисована (экономия энергии, fullscreen-игра, заблокирована сессия).

## Рассмотренные варианты

1. **В UI (JS setInterval)** — останавливается при засыпании вьюпорта, теряет срабатывания.
2. **В Rust-потоке** — независим от рендера, работает при закрытом UI, переживает перезапуск через БД.
3. **Task Scheduler Windows** — навязчиво, требует elevation, негибко.

## Решение

Вариант 2. Поток планировщика с собственным таймером (раз в 20 с сверка расписания с `next_fire_at` в БД), catch-up для пропущенных срабатываний (опция «выполнить пропущенное»), идемпотентность по `job_id`+`fire_at`.

## Последствия

Плюсы: надёжность, отсутствие пропусков, независимость от UI.
Минусы: логика cron дублируется в двух местах (предпросмотр дат в UI + исполнение в Rust) — общий крейт-парсер выносится в `vela-cron`.

## Условия пересмотра

Если потребуется системная интеграция (пробуждение из сна) — добавить опциональный Task Scheduler-шиму.
