# ADR-0003 — Blur mirror вместо чтения текстуры сцены

**Статус:** принято

## Контекст

Стеклянные панели должны размывать реальное содержимое фона. Первый эскиз предполагал чтение текстуры сцены A в UI B.

## Рассмотренные варианты

1. **Чтение текстуры из A** — невозможно напрямую: у каждого WebView2 свой D3D-контекст, общая текстура не шарится.
2. **Windows.Graphics.Capture между окнами** — работает, но +3–5 мс на кадр, задержка 1–2 кадра, мигание при перекрытиях.
3. **Blur mirror** — B рендерит собственную упрощённую копию сцены в offscreen-canvas 0.25× и размывает её шейдером.
4. **Имитация полупрозрачной плашкой** — дешево, но нечестно: содержимое не совпадает, «стекло» выглядит мёртвым.

## Решение

Blur mirror. Сцена описывается декларативно (слой-граф: цветовые поля, изображения, видео-кадр по требованию), поэтому B может построить её удешевлённую версию без обращения к A. Совпадение по композиции — попиксельное, по кадрам — не требуется, размытие скрывает разницу.

## Последствия

Плюсы: стоимость доли миллисекунды, нет задержки, нет мигания.
Минусы: сцену нужно описывать так, чтобы её можно было воспроизвести дважды (ограничение на шейдеры A); видео в зеркале — статичный кадр, обновляется 4 раза в секунду (незаметно под blur 28 px); игры в зеркале не отражаются — панель становится матовой.

## Условия пересмотра

Пересмотреть, если появится надёжный межоконный shared texture без задержки.
