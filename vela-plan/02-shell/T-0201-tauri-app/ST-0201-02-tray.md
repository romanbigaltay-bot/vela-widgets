# ST-0201-02 — Трей и меню

## 0. Фактическое состояние (2026-11-15)

Реализовано в `apps/desktop/src/tray.rs`:

- `TrayIconBuilder` с иконкой `tray-light.png`/`tray-dark.png`; выбор по
  `SystemUsesLightTheme` из реестра.
- Меню: `Показать виджеты` (чекбокс) и `Выход`. Левый клик по иконке
  переключает UI, правый открывает меню (`show_menu_on_left_click(false)`).
- Чекбокс не хранит отдельную правду: после каждого изменения он
  перезаписывается из `SurfaceManager::kind_visible`. Меню Tauri успевает
  переключить галочку само, поэтому `sync_check` обязателен.
- «Выход» — обычный пункт меню, а не `PredefinedMenuItem::quit`: сначала
  выставляется `quitting`, затем `app.exit(0)`, `RunEvent::Exit` уничтожает
  поверхности и закрывает БД.
- Пункты «сцена», «режим», «профиль», «настройки» отложены до T-0202…T-0205:
  пункт, который ничего не делает, выглядит сломанным.

Подтверждение AC:

| AC | Доказательство |
|---|---|
| AC-1 | в меню только реально работающие пункты; подменю профилей появится вместе с профилями (T-0305) |
| AC-2 | 6 переключений через `PostMessage`: медиана 21.71 мс, максимум 35.94 мс при пороге 100 мс |
| AC-3 | «Выход»: exit 0, `Get-Process vela` — 0; `RunEvent::Exit` вызывает `destroy_all` и `Prepared::shutdown` |

Отклонения: `Ctrl+Alt+Q` не реализован (T-0205), тост второго экземпляра
отложен, меню не пересобирается по `profile.changed` (профилей ещё нет).

Статус — `done` (2026-11-15).

## Цель

Управление приложением без открытия настроек: сцена, UI, режимы, профили, выход.

## Реализация

1. `TrayIconBuilder` с двумя иконками (light/dark) — выбор по теме панели задач
   (`HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\SystemUsesLightTheme`).
2. Меню: `Показать сцену ✓`, `Показать виджеты ✓`, подменю `Режим` (edit/locked/pass),
   подменю `Профиль` (динамически из БД), `Настройки…`, `Выход`.
3. Клик по иконке — toggle видимости UI.
4. Состояние меню синхронизируется из `SurfaceManager` и `layout` события;
   чекбоксы не живут отдельной правдой.
5. Меню пересобирается при изменении профилей (событие `profile.changed`).

## Критерии приёмки

- AC-1 Пункты меню активны только когда имеют смысл (нет профилей → подменю пустое).
- AC-2 Клик по иконке скрывает/показывает UI за ≤ 100 мс.
- AC-3 Выход корректно завершает все поверхности и поток cron (после P7).

## Тест-план

Ручной сценарий + интеграционный тест на изменение состояния меню после
программного переключения режима.

## Риски

Меню в Tauri 2 обновляется только пересозданием → частая пересборка даёт
мигание; батчить изменения через 50 мс.
