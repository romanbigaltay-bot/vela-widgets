# T-0203 — Поверхность B (UI)

## 1. Цель

Прозрачное окно над иконками, которое принимает мышь только там, где нужно,
не крадёт фокус у активного приложения и умеет три режима ввода.

## 2. Режимы ввода

| Режим | `WS_EX_TRANSPARENT` | Клики по виджетам | Клики по пустому месту | Фокус |
|---|---|---|---|---|
| `edit` | нет | работают | пан холста | забирается по клику |
| `locked` | нет | работают | уходят в приложение под окном | не забирается |
| `pass` | да (всё окно) | не работают | уходят под окно | не забирается |

**Ключевая проблема `locked`.** Окно занимает весь экран, поэтому клики по
пустому месту не доходят до приложений под ним. Решение: динамический
`WM_NCHITTEST` через `SetWindowSubclass` — возвращаем `HTTRANSPARENT` для
областей, где нет интерактивных элементов. Список «горячих» прямоугольников UI
присылает в Rust поверхность B (IPC `window.set_hit_regions`), обновляет его
при изменении раскладки (дебаунс 50 мс).

**Проблема `WS_EX_NOACTIVATE`.** С ним окно не получает клавиатуру даже при
клике на поле ввода. Решение: в `edit`/`locked` снимаем `WS_EX_NOACTIVATE` при
клике в поле ввода (IPC-сигнал от UI) и возвращаем обратно при потере фокуса;
для `pass` — всегда установлен.

## 4. Критерии приёмки

- **AC-1** В `pass` клик по экрану уходит в приложение под холстом (проверка
  на запущенной игре/проводнике).
- **AC-2** В `locked` клик по пустому месту проходит сквозь, клик по виджету —
  работает.
- **AC-3** Ввод текста в заметке работает; после `Escape` фокус возвращается
  приложению под окном.
- **AC-4** Окно не появляется в Alt+Tab и на панели задач.
- **AC-5** Прозрачность настоящая: видно сцену под панелями (не чёрный фон).
- **AC-6** Переключение режимов ≤ 30 мс, без мигания окна.

## 6. Риски

- R-08 (дрожание при 144 Гц) — здесь только окно, но флаги влияют на плавность;
  проверяется вместе с P3.
- Частые `SetWindowLongPtr` могут давать мерцание → менять стили только при
  реальном изменении, а не на каждый кадр.
