# ST-0203-02 — Хит-тест

## Цель

Клики по пустому месту проходят сквозь окно, по виджетам — попадают в UI.

## Реализация

1. `SetWindowSubclass` на HWND поверхности B: обработчик `WM_NCHITTEST`.
2. В состоянии хранится `Vec<Recti>` горячих областей (физические пиксели) +
   «весь экран горячий» флаг для `edit`.
3. `WM_NCHITTEST`: точка в области → `HTCLIENT`; иначе → `HTTRANSPARENT`.
4. IPC `window.set_hit_regions { monitor, rects, fullscreen_hot }` — вызывается
   UI при: изменении раскладки, скролле/зуме, открытии/закрытии панели
   (дебаунс 50 мс, отправка только при изменении).
5. В `pass` — весь экран `HTTRANSPARENT` без списка областей (быстрый путь).
6. Диагностика: `RUST_LOG=hit=debug` печатает прямоугольник и результат.

## Критерии приёмки

- AC-1 Клик по пустому месту в `locked` доходит до приложения под окном.
- AC-2 Клик по кнопке виджета работает в `locked`.
- AC-3 После перетаскивания виджета горячая область обновилась (без этого клик
  по старой позиции попадает/не попадает).
- AC-4 Точность совпадения границ ±1 px на 150 % DPI.

## Тест-план

Автотест: программно послать `WM_NCHITTEST` с координатами внутри/снаружи
области и проверить возвращённый код. Ручной тест с окном-свидетелем под холстом.

## Риски

Рассинхрон списка областей и реального DOM → правило: единственный источник —
`getBoundingClientRect` после `transform` мира; тест точности на 4 масштабах.
