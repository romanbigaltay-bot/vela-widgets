# ST-0202-03 — Восстановление и фолбэки

## Цель

Перезапуск Explorer и исчезновение WorkerW не должны требовать перезапуска
приложения.

## Реализация

1. `RegisterWindowMessageW("TaskbarCreated")` в главном окне-получателе;
   при получении: `SurfaceManager::reattach_all()`.
2. `reattach_all()`: заново `find_workerw()`, `SetParent` для A, восстановление
   z-порядка B/C, повторный `ShowWindow`. WebView2 **не** пересоздаётся.
3. Счётчик попыток: 3 с интервалом 300 мс; далее — фолбэк-режим.
4. Фолбэк: `SetWindowPos(HWND_BOTTOM)` без родителя, тост «Сцена работает
   в упрощённом режиме», флаг в настройках `scene.degraded = true`.
5. Выход из фолбэка автоматически при следующем успешном `reattach`.

## Критерии приёмки

- AC-1 После `taskkill explorer` + старта Explorer сцена вернулась ≤ 2 с.
- AC-2 Состояние сцены сохранено (не сброс на первый кадр).
- AC-3 Три неудачи подряд → фолбэк, приложение живо, тост показан.
- AC-4 Флаг `degraded` виден в настройках и сбрасывается при успехе.

## Тест-план

TC-0202-02 (замер восстановления), ручной тест с убийством Explorer дважды подряд.

## Риски

Explorer может перезапускаться чаще одного раза (обновление) — цикл должен
быть дешёвым и не спамить тостами (не более одного в 30 с).
