# ST-0202-02 — Геометрия и DPI

## Цель

Окно сцены точно совпадает с физическими пикселями монитора при любом масштабе.

## Реализация

1. `monitors::enumerate()` через `EnumDisplayMonitors` + `GetMonitorInfoW`;
   храним `{ id, rect_physical, work_area, dpi, primary }`.
2. Для каждой поверхности: `SetWindowPos` в **физических** координатах монитора
   (не в логических), чтобы избежать двойного масштабирования.
3. Per-monitor DPI awareness v2 в манифесте приложения
   (`dpiAwareness = PerMonitorV2`), иначе Windows растянет окно сама.
4. Обработка `WM_DPICHANGED` — применить `wParam` DPI, не масштабировать вручную.
5. `devicePixelRatio` в WebView2 обновляется сам; UI-слой обязан пересчитать
   мир (это делает P3).

## Критерии приёмки

- AC-1 Сцена занимает ровно весь монитор при 100/125/150/200 %.
- AC-2 Нет размытия текста сцены на 150 % (проверка по скриншоту и глазам).
- AC-3 При двух мониторах с разным DPI обе поверхности корректны.
- AC-4 После смены разрешения геометрия обновилась без артефактов.

## Тест-план

TC-0202-05; визуальная проверка скриншотов на каждой конфигурации из матрицы.

## Риски

Смешивание логических и физических координат — источник «половинчатых» багов;
правило: в `vela-platform` только физические пиксели, в UI — CSS-пиксели,
конвертация в одном месте.
