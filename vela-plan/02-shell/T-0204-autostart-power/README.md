# T-0204 — Автозапуск и питание

## 1. Цель

Приложение запускается вместе с Windows по желанию пользователя, корректно
реагирует на батарею, сон, блокировку и завершение сеанса.

## 2. Решения по автозапуску

- Основной способ — ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  (не требует прав администратора).
- Опция «Запускать для всех пользователей» → `HKLM` + Task Scheduler (требует
  elevation, отдельный флоу с UAC).
- Запуск с задержкой 5 с (после входа в сессию Explorer уже поднят), чтобы
  WorkerW существовал.
- Проверка после записи: ключ существует и путь корректен; при неудаче —
  понятное сообщение, а не молчание.
- Обновление приложения не должно ломать автозапуск: путь хранится без версии
  (стабильная папка `%LOCALAPPDATA%\Programs\Vela`).

## 3. Питание

| Событие | Реакция |
|---|---|
| Переход на батарею | сцена 30 fps, анимации виджетов 15 fps, обновить `power_state` |
| Батарея < 25 % | сцена на паузе, панели матовые (без blur) |
| `WM_POWERBROADCAST / PBT_APMSUSPEND` | остановить таймеры, flush БД |
| `PBT_APMRESUMEAUTOMATIC` | восстановить, catch-up cron (после P7) |
| `WTS_SESSION_LOCK` | пауза сцены и анимаций |
| `WM_ENDSESSION` | синхронный flush, быстрый выход ≤ 1 с |

## 5. Критерии приёмки

- **AC-1** Включение автозапуска → после перезагрузки приложение в трее.
- **AC-2** Выключение → в реестре нет записи, после перезагрузки не запускается.
- **AC-3** Замена бинаря (обновление) не ломает автозапуск.
- **AC-4** Отключение питания: сцена снижает fps ≤ 100 мс после события.
- **AC-5** Сон/пробуждение: таймеры не дают двойного срабатывания (после P4/P7).
- **AC-6** Завершение сеанса Windows: данные сохранены, выход ≤ 1 с.

## 7. Риски

- Политики домена могут запрещать `Run`-ключ → показывать реальную причину
  отказа (код ошибки) и предлагать Task Scheduler.
- Запуск до готовности Explorer → задержка 5 с и повторная попытка `reattach`.
