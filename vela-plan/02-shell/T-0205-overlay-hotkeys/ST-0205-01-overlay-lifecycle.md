# ST-0205-01 — Жизненный цикл оверлея

## Цель

Оверлей появляется на мониторе с курсором, забирает ввод, исчезает без следов.

## Реализация

1. `overlay::open(mode, monitor)`:
   - `GetCursorPos` → `MonitorFromPoint` → нужный монитор;
   - если C уже есть — переиспользовать, сменить маршрут;
   - создать `WebviewWindow` top-most, `WS_EX_TOOLWINDOW`, без `NOACTIVATE`;
   - `SetForegroundWindow`.
2. `overlay::close()` — сохранить состояние, `destroy()` окна.
3. Таймер простоя 5 с: после `close` не уничтожать сразу, ждать; при повторном
   открытии — переиспользовать (быстрее).
4. Возврат фокуса: сохраняется `prev_foreground` HWND при открытии; при
   закрытии — попытка `SetForegroundWindow(prev)`, при неудаче
   `AttachThreadInput` + повтор.
5. Событие `overlay.state_changed { open, mode }` — для трея и UI.

## Критерии приёмки

- AC-1 Открытие ≤ 120 мс на тёплом старте.
- AC-2 Фокус возвращается в 100 % попыток (тест 50 раз).
- AC-3 После уничтожения клики по виджетам работают.
- AC-4 Процессов `msedgewebview2` не прибавляется после 20 циклов.

## Тест-план

TC-0205-01, TC-0205-03.

## Риски

`destroy()` может не успеть освободить WebView2-процесс → ждать `Destroyed`
событие, а не только возврат из вызова.
