# T-0205 — Поверхность C и хоткеи

## 1. Цель

Слой для палитры команд, аннотатора и настроек: создаётся по требованию,
перекрывает всё, забирает клавиатуру, исчезает без следа. Плюс глобальные
хоткеи, которые не конфликтуют с системой.

## 2. Решения

- C создаётся лениво при первом вызове и **уничтожается** через 5 с простоя
  (экономия ~50 МБ). Состояние оверлея (что было открыто) хранится в Rust.
- Режимы оверлея: `palette`, `annotator`, `settings`, `onboarding`.
  Один C на все мониторы — на мониторе с курсором.
- Затемнение: полупрозрачный слой внутри C (`rgba(0,0,0,.28)`), не DWM.
- Фокус: `SetForegroundWindow` + `AttachThreadInput` при отказе; при закрытии —
  возврат фокуса предыдущему окну.
- Хоткеи через `RegisterHotKey` (не LL-хук) — минимальные привилегии:
  `Ctrl+Alt+K` палитра, `Ctrl+Alt+E/L/P` режимы, `Ctrl+Alt+T` тема,
  `Ctrl+Alt+S` скриншот (P5), `Ctrl+Alt+Q` выход. Все — настраиваемые,
  с проверкой занятости (`ERROR_HOTKEY_ALREADY_REGISTERED`).

## 4. Критерии приёмки

- **AC-1** Палитра открывается за ≤ 120 мс, закрывается по `Escape`, фокус
  возвращается.
- **AC-2** C не существует в памяти, когда не нужен (проверка по числу процессов).
- **AC-3** Занятый другим приложением хоткей → понятная ошибка, предложение
  выбрать другой.
- **AC-4** Хоткеи работают при активном fullscreen-приложении (кроме
  исключённых пользователем).
- **AC-5** После закрытия C виджеты снова получают клики.

## 6. Риски

- R-03 (антивирус и хоткеи) — используем `RegisterHotKey`, а не LL-хук.
- Частое создание/уничтожение C даёт фризы → таймаут 5 с и «тёплый» кэш
  последнего состояния оверлея.
