# AGENTS.md — Vela

> Инструкции для агентов и разработчиков, которые продолжают этот проект.
> Снимок проверки: **2026-11-02**. Проверено чтением файлов; `cargo` и `pnpm`
> в текущем окружении отсутствуют, поэтому тесты и линты здесь не перезапускались.

## 1. Что это за проект

**Vela** — фоновый слой рабочего стола Windows 11: живой фон (фото, видео,
2D/3D, игра), бесконечный холст с виджетами и стеклянные панели. План состоит
из этапов **P1–P8**; текущая реализация — только **P1 «Каркас и контракты»**.

Это ещё **не работающее desktop-приложение**:

- Tauri намеренно не подключён в P1 (появится в P2, `ST-0201-01`);
- `cargo run -p vela` открывает/мигрирует SQLite и завершается, окна нет;
- UI — скелет Vite + React; полноценных токенов, тем и стекла нет (`T-0103`);
- холста, виджетов, сцены и захвата экрана ещё нет.

## 3. Источники истины и порядок чтения

1. **Объём и требования** — `vela-plan/PLAN.md`, затем README этапа, README
   задачи и файл подзадачи. Не начинай работу по памяти: открой ТЗ своей
   подзадачи.
2. **Архитектурные решения** — `vela-plan/00-conventions/04-adr/`. ADR
   авторитетнее обзорных документов, но фактический код может расходиться с
   ADR; расхождение нужно явно исправлять, а не молча выбирать одну сторону.
3. **Что реально существует** — код, тесты, SQL-миграции и конфиги в
   `vela-app`. Документы часто описывают целевое состояние, а не текущее.
4. **Статус** — `vela-app/docs/STATUS.md` задуман как живой снимок, но сейчас
   содержит противоречия (см. §7). Не доверяй числам «4 из 8», «2 из 4» и
   «8 коммитов» без проверки.
5. **Прототип** — `vela-demo/vela-canvas.html` только визуальный референс.
   Любой токен или поведение из него должны быть сначала описаны в плане
   (`PROTOTYPE.md`), а не переноситься в код «как есть».

Корневые `STATUS.md` и `SESSION.md` **байт-в-байт совпадают** с копиями в
`vela-app/docs/`. Пока дублирование не устранено, считай канонической копию в
`vela-app/docs/` (она лежит рядом с кодом и CI), а корневую — зеркалом. Не
редактируй обе копии по отдельности.

## 5. Команды

### Rust

```bash
cd vela-app

cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test -p vela-core --test sql_rules
cargo run -p vela                 # создаёт/мигрирует БД и выходит; окна нет

# В Git Bash / WSL (в текущем PATH bash отсутствует):
"C:\Program Files\Git\bin\bash.exe" scripts/arch-check.sh
```

`cargo run -p vela` — это проверка связности крейтов и кодов возврата
`0/1/2`, а не запуск GUI. Для GUI нужен P2.

### UI

```bash
cd vela-app/ui

pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm test
pnpm format:check
pnpm ipc:check
pnpm dev
```

Генерация контрактов:

```bash
cd vela-app/ui
pnpm ipc:gen       # требует cargo; пишет в src/shared/api/
```

Важно:

- `pnpm ipc:gen` идемпотентна и запускает Rust-тест с фичей `ts-export`.
- Сгенерированные файлы в `ui/src/shared/api/` не редактируются вручную.
- **`pnpm size` сломан**: файла `scripts/size-report.mjs` нет. Не используй его
  как проверку и не считай отсутствие отчёта доказательством размера.
- `pnpm check` — это `typecheck + lint + test + format:check`; он не включает
  `ipc:check`.

### CI

CI лежит в `vela-app/.github/workflows/ci.yml`. GitHub Actions читает
`.github/workflows` **только в корне репозитория**. Если инициализировать git в
`vela-vijets`, этот workflow не запустится: его нужно перенести в корневой
`.github/workflows/` и поправить рабочие каталоги. Если репозиторий — сам
`vela-app`, всё работает как задумано. Сначала реши границу репозитория (§7).

## 6. Архитектурные инварианты

### Поверхности и процесс

- Три поверхности: **A/Scene** (под иконками, WorkerW), **B/UI** (над
  иконками, ввод), **C/Overlay** (top-most, палитра/аннотации/настройки).
- Один процесс приложения; WebView2 сам создаёт рендер-процессы.
- Тяжёлые данные (кадры, снимки) не гоняются через IPC: передаётся путь к
  файлу в кэше, а не содержимое.
- В P1 поверхности и Tauri отсутствуют. Не добавляй Win32-код в `vela-core`.

### Владение состоянием

| Данные | Владелец |
|---|---|
| Раскладка, элементы, настройки | SQLite (`state.db`), кэш в Zustand |
| Режим ввода, зум/пан | Zustand (поверхность B) |
| Позиция/размер окон, z-order | Rust |
| Состояние планировщика | Rust, поток cron |
| Тема | SQLite + `prefers-color-scheme`, CSS-переменные |

UI никогда не пишет в SQLite напрямую — только через типизированную IPC-команду.

### Границы крейтов

- `vela-core` — домен. **Запрещены** `tauri`, `windows`, `winit`, `wgpu`,
  `tokio` и зависимости от других крейтов проекта. Проверяется
  `tests/arch_rules.rs`, `tests/graph_rules.rs` и `scripts/arch-check.sh`.
- `vela-ipc` — контракты. Запрещены `tauri`, `windows`, `winit`, `wgpu`.
- `vela-platform` — Win32; запрещён `tauri`.
- `vela-cron` — cron-парсер и планировщик, без UI.
- `vela` (`apps/desktop`) — граница приложения; здесь появится Tauri.

### БД и миграции

- SQLite, WAL, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout`.
- Соединение не покидает поток-владелец; API — через `Db::call`. **Не тяни
  tokio в `vela-core`** ради `spawn_blocking` (это уже зафиксировано в `D-7`).
- Миграции — SQL-файлы, вшитые через `include_str!`, по одной транзакции на
  файл, с бэкапом перед обновлением. Есть bootstrap-таблица
  `schema_migrations`; это осознанное исключение (`D-9`).
- В запросах — только явные колонки, **никакого `SELECT *`**; правило
  проверяется `sql_rules.rs`.
- Временные метки — `i64` миллисекунды UTC.
- Не создавай репозиторий «на будущее» без потребителя (см. `D-13`).

### IPC и UI

- Ответы идут в `Envelope<T>` (`ok`, `data`, `error`); ошибки — `VelaError` с
  `ErrorCode`, UI реагирует на `code`, а не на текст.
- В компонентах **нельзя** импортировать `@tauri-apps/api/core` и вызывать
  `invoke` напрямую. Только `call()` из `shared/api/client`.
- События — через `on()` / `useEvent`; подписка обязана сниматься при
  размонтировании.
- Запрещены `console.*` вне логгера, `any`, `!` (non-null assertion), прямые
  `requestAnimationFrame` и `setInterval` вне соответствующих сервисов.
- Стили — CSS-переменные/токены; Tailwind не используется. Никаких магических
  цветов. Стекло — только `.glass`, без вложенности.
- Генерируемые типы не форматируются Prettier и не правятся руками;
  см. `ui/.prettierignore` и `ipc-gen.mjs`.

### Энергия и производительность

- Idle = 0 кадров; при батарее — 30 fps; fullscreen-игра — пауза.
- Blur mirror: 30 fps, пока видна стеклянная панель; 4 fps для статичной сцены;
  0 fps, если панелей нет. Это правило из `T-0304`; не путай с «20–30 fps» из
  `PLAN.md` и «4 fps» из ADR-0003 — документы пока расходятся.
- Стекло пересчитывается при изменении сцены/геометрии, а не каждый кадр.
- Любая анимация должна останавливаться при `document.hidden` и отсутствии
  изменений.

## 8. Правила работы

1. **Одна подзадача — один PR.** Заголовок: `[ST-0304-02] …`; сообщение
   коммита: `vela: [ST-0304-02] …`. Исключение — несколько подзадач одной
   задачи, если каждая меньше 0.5 дня (не более трёх).
2. **Статус меняется только по доказательствам.** `done` требует: AC
   выполнены построчно, тесты/линты/формат зелёные, ручной сценарий пройден,
   план обновлён. Если проверку нельзя выполнить (нет `cargo`, нет CI), статус
   остаётся `in-progress`/`review`, а не «почти done».
3. **План обновляется вместе с кодом.** При закрытии задачи: README задачи,
   `manifest.json` (`status`, `closed_at`), при необходимости `INDEX.md`.
   Обнаружил объём вне плана — заведи подзадачу, не делай «молча».
4. **Архитектурное изменение — новый/переписанный ADR** и ссылки из
   затронутых задач. Не решай архитектуру в комментарии к коду.
5. **Сначала проверь факт.** Документы в этом проекте уже расходятся; перед
   изменением открой код и тест, а не только README.
6. **Не добавляй зависимости без нужды.** Особенно `tokio`, `tauri`,
   `windows` в домен; `zod` — только если действительно включаешь dev-валидацию.
7. **Не редактируй сгенерированные файлы.** Меняй Rust-типы и запускай
   `pnpm ipc:gen`; проверяй `pnpm ipc:check`.
8. **Тесты — на поведение.** Для оконных/Win32-тестов обязателен `Drop`-гарант.
   Негативные проверки (что запрет действительно запрещает) приветствуются.
9. **Без сети и телеметрии по умолчанию.** Сеть — только по явному действию
   пользователя (погода, ICS, тикер). Приватные данные — отдельно, с
   опциональным DPAPI-шифрованием.
10. **Не удаляй незнакомые файлы/изменения.** Если файл выглядит чужим,
    сначала выясни его происхождение; это может быть незакоммиченная работа.
